# 契约目录（冻结区）

本目录是甲、乙两方独立开发、最终合并即可运行的**唯一依据**。

## 铁律

1. **本目录任何文件不得修改。** 需要变更时，两人当面确认后由一人改，另一人同步，并在下方变更记录追加一行。
2. 甲、乙各自把整个 `contract/` 目录复制到自己的工作目录，作为只读参考。
3. 合并时 `contract/` 以甲的版本为准（两份应完全一致）。

## 文件

| 文件 | 内容 |
|---|---|
| `API-CONTRACT.md` | 全部 HTTP / WebSocket 接口定义，前后端、后端与算法服务之间的所有交互 |
| `DB-SCHEMA.md` | MySQL 表结构与归属，演示账号、种子数据 |

## 最终合并后的目录结构

```
Zhi_softwire/
├── docker-compose.yml      乙
├── .env.example            乙
├── contract/               冻结区（本目录）
├── backend/                甲 独占，任何文件乙不得创建或修改
├── algo-service/           乙 独占
├── frontend/               乙 独占（由现有 raspi 迁移而来）
└── deploy/                 乙 独占
```

合并动作 = 把三个顶层目录并排放好。**两人的文件路径零交集，不存在冲突。**

## 服务与端口

| 服务 | 容器名 / 主机名 | 端口 | 负责人 |
|---|---|---|---|
| MySQL 8.0 | `mysql` | 3306 | 甲（建表脚本） |
| Redis 7 | `redis` | 6379 | 甲（使用方） |
| 后端安全内核 | `backend` | 8000 | 甲 |
| 算法服务 | `algo-service` | 8100 | 乙 |
| 前端 | `frontend` | 80（生产）/ 5173（开发） | 乙 |

调用方向是单向的，不存在环：

```
浏览器 ──HTTP/WS──> frontend(nginx) ──代理──> backend:8000 ──HTTP──> algo-service:8100
                                                  │
                                                  ├──> mysql:3306
                                                  └──> redis:6379
```

**前端永远不直接调用 algo-service。** 所有算法调用必须经过 backend，以满足需求文档"统一鉴权网关 + 全链路审计埋点 + 存证上链"的要求。
