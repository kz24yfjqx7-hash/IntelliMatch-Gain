# 答辩演示剧本（十步）

> 故事线来自《分工概要》第八节。每步：**操作** → **预期现象** → **讲解话术** → **兜底方案**。
> 全程在 `http://<演示机IP>` 进行；建议双显示器：左屏页面、右屏 `docker compose logs -f backend algo-service`（可选）。
>
> **演示前 30 分钟检查清单**
> 1. `docker compose ps` 五个服务 healthy；`curl localhost/api/v1/health` 返回 `code:0`
> 2. 浏览器清缓存、关掉无关标签；准备两个浏览器（或一个普通 + 一个无痕）分别登 `admin` 与 `vpp`/`subject`
> 3. 提前把 `VITE_USE_MOCK=true` 版本的前端镜像备在本机（`energy-tds/frontend:1.0-mock`），或准备 `npm run dev` 终端
> 4. 若联网：确认 `.env` 的 `DEEPSEEK_API_KEY` 有效；若不联网：确认 `cache/deepseek_cache.json` 已预热
> 5. 找到一条任务 traceId 备用（第 9 步会用第 5/7 步产生的）

## 兜底总则（MSW 模式）

后端 / 数据库在现场挂掉时，**前端可以完全脱离后端运行**：`frontend/src/mocks/` 内置 MSW 假后端，实现了契约第二部分全部接口，含本地哈希链、权限矩阵、JS 版 FedAvg（真算）。切换方式二选一：

- 方式 A（已备镜像）：`docker compose stop frontend && docker run -d --rm -p 80:80 --name tds-mock energy-tds/frontend:1.0-mock`
- 方式 B（开发服务器）：`cd frontend && VITE_USE_MOCK=true npm run dev -- --host --port 80`（或 3000）

切换耗时 < 30s；切换后以下每一步的"兜底方案"均指在 MSW 模式下的等效操作。讲解时不必强调是模拟——MSW 的数据与链式校验逻辑与真实后端一致。

---

## 第 1 步：admin 登录 → 首页驾驶舱

- **操作**：打开首页 → 登录页输入 `admin / admin123` → 进入 `/cloud/topology`
- **预期**：顶部 `TrustFlowBanner` 六环节流程图（身份接入→数据登记→权限授权→隐私计算→智能调度→存证审计）各有计数；右上角显示用户名 / 角色 / 告警铃铛；拓扑图 4 个边缘节点在线，WebSocket 每几秒刷新节点指标
- **话术**："平台以 DID 身份为起点，数据登记、授权、隐私计算、调度、存证串成一条可信闭环。上方六个环节的数字全部来自后端实时统计，后面每一步都会让其中一个数字 +1。"
- **兜底**：MSW 模式下种子数据同样有 6 账号、4 节点、80 条资产，流程图计数照常

## 第 2 步：身份接入中心 — 现场注册设备 DID

- **操作**：左侧「身份接入中心」`/identity` → 「注册 DID」→ 类型 `device`、名称「答辩现场逆变器-01」、所属机构 → 提交 → 列表出现新 DID → 点「DID 文档」→ 点「验签」（输入任意消息，使用系统生成的签名）
- **预期**：DID 形如 `did:vpp:device:<hash>`；文档含 `@context: https://w3id.org/did/v1`、`verificationMethod`（SM2 公钥）；验签弹出「验签通过」；日志栏出现「DID 注册」与「存证写入」两条；流程图「身份接入」计数 +1
- **话术**："每个设备都是一个自主身份，公钥上链、私钥留在设备。验签通过说明后续这台设备的任何数据都可以追溯到它本身。"
- **兜底**：MSW 的 `did.js` handler 生成同格式 DID 与文档；验签在浏览器内用相同规则校验

## 第 3 步：数据资产中心 — 登记光伏数据 → 自动分级 → 上链

- **操作**：「数据资产中心」`/assets` → 「登记资产」→ 类型 `pv`、选择刚才的 DID 为所有者、敏感度 / 粒度 / 数据量按默认 → 提交 → 查看详情 → 「溯源」
- **预期**：分级结果 `L3`（k-means 聚类 + 规则加权，详情显示 `clusterCenters`）；`payloadHash` 为 `sm3:...`；详情里有 `evidenceId` 与区块高度；流程图「数据登记」+1、「存证审计」+1
- **话术**："分级不是人工填的，是算法服务用 k-means 对敏感度、粒度、数据量聚类后再叠加规则判定的 L3。摘要用国密 SM3，写入本地哈希链，后面第 8 步我们会当场篡改它试试。"
- **兜底**：MSW 内 `classifyAssets` 用同样的三特征规则给出 L3；`chain.js` 本地链同样产生高度与哈希

## 第 4 步：权限控制中心 — subject 申请 → admin 审批

- **操作**：第二个浏览器登 `subject / subject123` → `/permission` → 「申请权限」→ 选第 3 步的资产、操作 `asset:read`、说明「用于负荷预测」→ 提交；切回 admin 浏览器 → 「待审批」→ 「通过」；回到 subject 浏览器刷新 → 「我的授权」出现记录
- **预期**：审批后 `listGrants` 出现新授权；权限矩阵页显示角色-操作矩阵；日志栏出现 `perm_change_log` 留痕；流程图「权限授权」+1
- **话术**："权限申请—审批—生效三步都留痕并存证，矩阵是后端真实生效的访问控制，不是前端的开关。下一步我们故意违规一次。"
- **兜底**：MSW 权限矩阵真的生效，审批流程在内存数据库中同样流转

## 第 5 步：越权演示 — vpp 下发调度被拦截

- **操作**：第二个浏览器改登 `vpp / vpp123` → 「云端调度」→ 任选一条已生成策略的任务 → 点「签名下发」（若按钮被 `v-permission` 隐藏，则用页面上的「越权演示」按钮，或在浏览器控制台调用 `issueDispatchTask`）
- **预期**：请求返回 `code 1003`，页面 toast「越权操作已被拦截」；**admin 浏览器右上角铃铛 +1，弹出 R01 告警**（WebSocket `audit_alert`）；审计中心出现一条 `risk_level=high` 日志；记下该 traceId
- **话术**："vpp 运营商没有 `dispatch:issue` 权限。后端在网关层拦截、写高风险审计日志、通过 WebSocket 秒级推送告警到管理员屏幕。注意这条 traceId，第 9 步我们用它把整条链路查出来。"
- **兜底**：MSW `dispatch` handler 对 vpp 返回 1003，`wsMock` 推 `audit_alert`(R01) 并写 high 日志，现象完全一致

## 第 6 步：隐私计算 — 联邦学习实时收敛

- **操作**：admin → 「隐私计算」→ 新建 FL 任务：4 节点、10 轮、ε=1.0、Top-k 10% → 「启动」
- **预期**：收敛曲线每约 1 秒长一个点（`fl_progress` WebSocket），loss 下降 / acc 上升；隐私预算条逐轮消耗 `epsilonSpent`；每轮显示 `gradientHash` 与存证高度；压缩率 90%；可选：勾选「模拟投毒 Node-C」重跑一次 → 出现 `gradient_poisoning` 异常标记
- **话术**："原始数据不出节点，只交换加了差分隐私噪声、Top-k 稀疏化后的梯度。每轮梯度哈希上链，任何一个节点事后抵赖都能对账。ε 预算用完任务会自动停止——隐私不是口号，是可以量化、会耗尽的资源。"
- **兜底**：MSW 内用 JS 复刻的小型 FedAvg 真算（MLP + 高斯噪声 + Top-k），曲线仍随参数变化

## 第 7 步：云端调度 — DQN 策略 → DeepSeek 解释 → 签名下发 → 回执

- **操作**：「云端调度」→ 「新建任务」→ 「运行 DQN」→ 查看各节点动作 / 功率 / 约束校验 → 「AI 解释」→ 「签名下发」（admin）→ 切到「终端响应」页看边缘节点回执
- **预期**：策略表显示每节点 `charge/idle/discharge` 与 `powerKw`，`constraintsChecked` 显示 SOC 20~95%、≤30kW 检查；AI 解释为中文段落，右上角徽章显示 `source=live`（联网）或 `cache`（断网）；下发后 `dispatch_progress` 推送，终端页出现 `ack`；调度流程图计数 +1
- **话术**："DQN 在开发机上训练好权重，边缘树莓派只做推理、200ms 内出结果。DeepSeek 负责把 Q 值差翻译成调度员能看懂的理由；断网时自动切到预热缓存，徽章会如实标明来源。下发必须由有权限的账号 SM2 签名，终端验签后才执行并回执。"
- **兜底**：MSW 的 dispatch handler 给出固定但合理的策略与规则模板解释（`source=rule`）

## 第 8 步：防篡改演示 — 篡改存证 → 校验标红 → 链断裂点

- **操作**：「存证中心」`/evidence` → 选第 3 步那条资产存证 → 「篡改演示」→ 修改任意字段值 → 确认 → 页面自动触发「完整性校验」与「链状态」
- **预期**：校验结果 `intact:false`，该条目整行标红并显示「重算哈希 ≠ 链上哈希」；链状态面板显示断裂高度 `brokenAt`，之后的区块标黄「受影响」；日志栏出现 tamper 与 verify 两条
- **话术**："存证的价值就在于改不了、一改就知道。我们直接改数据库快照，重算 SM3 与链上 block_hash 对不上，而且因为后一块包含前一块哈希，断裂点之后整条链都能被指认。"
- **兜底**：MSW `chain.js` 真的改 payload 并让 `verify` / `chain/status` 检测到同一断裂点

## 第 9 步：审计中心 — traceId 查完整链路

- **操作**：「审计中心」→ traceId 输入框粘贴第 5 步（或第 7 步）的 traceId → 查询 → 展示时间轴；再点「生成日报」
- **预期**：`el-timeline` 从登录 → 鉴权 → 越权拦截 → 告警 → 存证逐步展开，每步有时间、actor、资源；日报含 `narrative` 自然语言段落与 `narrativeSource` 徽章；「导出 CSV」下载成功
- **话术**："每个请求从进网关起带一个 traceId 贯穿前端、后端、算法服务、存证链。监管方拿一个 ID 就能还原谁、何时、对什么、做了什么、结果如何。日报的解读由 DeepSeek 基于统计数据生成。"
- **兜底**：MSW 审计 handler 按 traceId 聚合内存日志，时间轴同样可展示；日报 narrative 走规则模板

## 第 10 步：拔网线 — 全功能离线

- **操作**：当场拔掉演示机网线（或关 Wi-Fi）→ 再做一次第 7 步的「AI 解释」→ 随便再走一遍第 2 步注册 DID
- **预期**：页面无任何报错；AI 解释徽章从 `live` 变成 `cache`（或 `rule`），内容仍是通顺中文；其它功能（注册、登记、FL、调度、存证、审计）完全正常
- **话术**："整套平台不依赖任何外网服务：模型在本地、存证链在本地、数据库在本地。唯一的外部依赖是大模型解释，断网就降级到预热缓存，并且如实标注来源。这也是它能装进树莓派放到变电站现场的原因。"
- **兜底**：本步天然就是兜底场景；若连后端也挂了，切 MSW 模式后仍可完成所有操作

## 应急速查

| 状况 | 动作（≤ 30s） |
|---|---|
| 页面白屏 / 502 | `docker compose restart frontend backend`；仍不行 → 切 MSW（见兜底总则） |
| WebSocket 不推送 | 刷新页面（自动重连，指数退避）；检查是否走的 80 端口 |
| FL 曲线不动 | `docker compose logs --tail=30 algo-service`；重启 algo-service 后重新启动任务 |
| DeepSeek 超时卡顿 | 正常会在 `DEEPSEEK_TIMEOUT=8s` 后降级；不想等就先拔网线 |
| MySQL 崩 | `docker compose up -d mysql`，等 healthy 再 `up -d backend`；超过 1 分钟 → 切 MSW |
| 树莓派卡顿 | 关掉右屏日志终端；Chromium 只留一个标签；必要时 `docker compose stop algo-service` 在 FL 步骤前再 start |
