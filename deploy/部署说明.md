# 部署说明（docker compose 方式）

> 适用于：开发联调机、有 Docker 的演示机。**没有 Docker / 没有网络的目标机请用 `packaging/` 离线安装包**（见 `packaging/部署说明.md`）。

## 1. 前置条件

| 项 | 要求 |
|---|---|
| 系统 | Linux x86_64 或 aarch64（树莓派须 64 位系统，`uname -m` = `aarch64`） |
| Docker | 20.10+，含 `docker compose` 插件（v2） |
| 内存 | ≥ 3.5GB（树莓派 4GB 机型可行） |
| 磁盘 | ≥ 8GB |
| 目录 | `backend/`（甲）、`algo-service/`、`frontend/`、`contract/` 并排放在同一根目录 |

## 2. 一条命令启动（合并后）

```bash
cp .env.example .env            # 变量名见 contract/API-CONTRACT.md 第四部分
docker compose up -d --build    # 首次构建 3~10 分钟（取决于网络）
docker compose ps               # 五个服务应为 healthy / running
curl -s localhost/health        # backend 探活：{"status":"ok",...}（根路径 GET /health，经 nginx 反代；/api/v1/health 不存在）
# 浏览器打开 http://localhost   admin / admin123
```

服务拓扑：

```
浏览器 → frontend(nginx :80) ─ /api/ ─→ backend:8000 ─→ algo-service:8100
                              └ /ws  ─→ backend:8000 ─→ mysql:3306 / redis:6379
```

只有 `frontend` 对宿主机暴露端口（`FRONTEND_PORT`，默认 80）；其它服务只在 `energy-tds-net` 网络内可达。

## 3. 乙方独立联调（没有 backend/）

```bash
cp .env.example .env
docker compose -f docker-compose.dev.yml up -d --build                 # 仅算法服务 → localhost:8100
curl -s localhost:8100/algo/v1/health
docker compose -f docker-compose.dev.yml --profile mock up -d --build  # 再加一个 MSW 模式前端 → localhost:80
```

也可以不走容器：`cd algo-service && ../.venv/bin/uvicorn main:app --port 8100`，`cd frontend && VITE_USE_MOCK=true npm run dev`。

## 4. 常用操作

```bash
docker compose logs -f backend            # 看某个服务日志
docker compose restart algo-service       # 重启单个服务
docker compose build frontend && docker compose up -d frontend   # 改前端后只重建前端
docker compose down                       # 停止（保留数据卷）
docker compose down -v                    # 停止并清空数据库（下次启动会重新执行 backend/sql）
```

## 5. 离线镜像包（单架构，开发快速分发）

```bash
./deploy/build-offline.sh                 # 产出 dist/energy-tds-images-<arch>-<日期>.tar.gz
./deploy/build-offline.sh --skip-backend  # 没有 backend 时
./deploy/build-offline.sh --mock          # 前端打成 MSW 兜底版本
# 目标机（已有 Docker）：
mkdir energy-tds && tar -xzf energy-tds-images-*.tar.gz -C energy-tds && cd energy-tds && sudo ./load-offline.sh
```

## 6. 常见问题

| 现象 | 原因 / 处理 |
|---|---|
| `docker compose up` 报 `path "./backend" not found` | 甲方代码未合并。只联调乙方部分请用 `docker-compose.dev.yml` |
| mysql 一直 `starting`，backend 起不来 | 首次初始化在执行 `backend/sql/*.sql`，树莓派 SD 卡可能 2~3 分钟；`docker compose logs mysql` 看进度 |
| 改了 `MYSQL_*` 密码后 backend 连不上库 | 数据卷里已是旧密码。`docker compose down -v` 后重启（会清库） |
| 80 端口被占用 | 改 `.env` 的 `FRONTEND_PORT=8080`，`docker compose up -d frontend` |
| 前端 502 | backend 未就绪；nginx 使用惰性 DNS，backend 起来后自动恢复，无需重启 nginx |
| WebSocket 连不上 | 确认浏览器访问的是 nginx 端口而不是 5173 开发端口；nginx 已配 `Upgrade` 头与 3600s 超时 |
| DeepSeek 解释显示 `source=cache/rule` | 未配置 `DEEPSEEK_API_KEY` 或断网，属正常降级；配置 key 后 `docker compose restart algo-service` |
| 树莓派内存告急 | 用 `packaging/assets/mysql-arm64.cnf` 替换 `deploy/mysql/mysql.cnf`（`performance_schema=OFF`，`innodb_buffer_pool_size=128M`），并把 swap 调到 2GB |
| 需要 MSW 兜底模式 | `.env` 设 `VITE_USE_MOCK=true` 后 `docker compose build frontend && docker compose up -d frontend`（前端完全在浏览器内模拟后端） |
| 镜像构建被墙 | 给 Docker 配置镜像加速；或在能联网的机器用 `deploy/build-offline.sh` 打包后拷贝 |

## 7. 文件一览

| 文件 | 用途 |
|---|---|
| `docker-compose.yml` | 五服务生产 / 联调编排 |
| `docker-compose.dev.yml` | 乙方独立联调（algo-service + 可选 MSW 前端） |
| `.env.example` | 环境变量模板（contract 第四部分） |
| `deploy/nginx.conf` = `frontend/nginx.conf` | 前端 nginx：静态托管 + `/api/`、`/ws` 反代 |
| `deploy/mysql/mysql.cnf` | MySQL 标准配置 |
| `deploy/build-offline.sh` / `load-offline.sh` | 单架构离线镜像包 |
| `deploy/答辩演示剧本.md` | 十步演示话术与兜底方案 |
| `packaging/` | 正式双架构离线安装包 |
