## 1. MySQL 建表与种子数据 ★最关键的一项

建表脚本从没在真 MySQL 上跑过，这一步失败的概率最高。

```bash
cd <项目根目录>

docker run -d --name tds-mysql -p 3306:3306 \
  -e MYSQL_ROOT_PASSWORD=root123 \
  -e MYSQL_DATABASE=energy_tds \
  -e MYSQL_USER=energy \
  -e MYSQL_PASSWORD=energy123 \
  -v "$PWD/backend/sql:/docker-entrypoint-initdb.d:ro" \
  mysql:8.0

# 种子有 57 万行 SQL，等它跑完，大约 30~90 秒
sleep 60
docker logs tds-mysql 2>&1 | grep -iE "error|denied|failed"
```

**期望：上面这条 grep 没有任何输出。**

> 有输出就把完整报错贴给我。最可能的两类问题：
> ① ENUM 值写错（比如 `load` 是 MySQL 保留字，我已改成 `load_kw` 规避）；
> ② `PREPARE stmt FROM @s` 在 initdb 环境里被拒——真出现的话把 02_seed.sql
> 末尾那段动态建表改成写死当月表名即可。

### 1.3 存证哈希链在数据库里是连续的

纯 SQL 校验，不用起后端：

```bash

-- 每个区块的 prev_hash 必须等于前一个区块的 block_hash，断链数必须是 0
SELECT COUNT(*) AS 断链数
FROM chain_evidence a JOIN chain_evidence b ON a.block_height = b.block_height + 1
WHERE a.prev_hash <> b.block_hash;

-- 高度必须从 0 开始且连续无重复
SELECT MIN(block_height) AS 起始高度, MAX(block_height) AS 最大高度,
       COUNT(*) AS 总数, COUNT(DISTINCT block_height) AS 去重后;
SQL
```

"""并发写 20 条存证，验证不会出现重复的 block_height。"""
import concurrent.futures as cf
from core.database import SessionLocal
from modules.evidence.chain import LocalHashChain

chain = LocalHashChain()

def write(i):
    with SessionLocal() as db:
        r = chain.write(db, category="data", ref_id=f"concurrent-{i}",
                        payload={"i": i}, actor_did=None, trace_id="tr-concurrency-test")
        db.commit()

with cf.ThreadPoolExecutor(max_workers=8) as pool:
    heights = list(pool.map(write, range(20)))

print("写入高度:", sorted(heights))

with SessionLocal() as db:

## 附：需要和乙同步的五件事

1. **docker-compose 的 mysql 服务必须写成
   `command: --default-authentication-plugin=mysql_native_password --performance-schema=OFF`**，
   两个参数缺一不可。`--performance-schema=OFF` 是内存：不加的话树莓派上光 MySQL
   就吃掉 400MB。认证插件那个是**连都连不上**：MySQL 8 默认 `caching_sha2_password`，
   pymysql 走 TCP 握手要 `cryptography` 包，而我们为了 arm64 构建刻意没装它
   （装了会拖进 Rust 工具链，树莓派镜像直接卡死）。这条是本地实测撞出来的，
   不加的话后端起来第一件事就是连库失败。
2. **`did_key` 表多了两列** `private_key_enc` / `custody`：演示账号的私钥由平台
   用 SM4-CBC 加密托管，否则答辩现场没有任何一把私钥可以用来演示「签名下发」。
   乙不直连数据库，不影响接口，但前端在做身份接入中心页时可以把 `custody` 字段展示出来。
3. **多了一张契约外的表 `algo_risk_assessment`**，用来支撑 `GET /risk/history`——
   契约 2.12 有这个接口但表清单里漏了。同样不影响乙，周五合并时在
   `contract/README.md` 变更记录补一行即可。
4. **登录接口现在会返回 1007**：同一账号 5 分钟内密码错 5 次就临时锁定。
   错误码在契约 1.1 里本来就有，不算改契约，但**前端登录页要把这个 message
   原样显示出来**——只提示「用户名或密码错误」的话，用户会一直以为是自己记错了密码。
