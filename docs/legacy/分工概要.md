# 能源可信数据空间平台 — 两人分工概要

> 给甲、乙两人共同阅读。开工前请务必读完，尤其是「铁律」和「合并方式」两节。

## 一、项目目标

把现有的 `raspi`（纯前端离线演示沙盘）升级为符合两份需求文档的**能源可信数据空间平台**：
前后端分离，具备可信身份（DID）、数据可信存证、细粒度权限控制、隐私计算、智能调度、安全审计六大能力。

**定位：答辩/评审演示为主。** 因此：

- MySQL、RBAC、审计、存证**全部做真的**——这些是评委会点开看的
- 联盟链用 `LocalHashChain`（本地哈希链）替代 Fabric，但**防篡改能力要能现场演示**
- MQTT 用边缘模拟器替代真实设备
- 联邦学习、差分隐私、Top-k、DQN **必须是真算法**，不是假动画。现场能改数据、重跑、看曲线变化，这是最大的加分项

## 二、成果拆成三个独立目录

| 目录 | 负责人 | 内容 | 技术栈 |
|---|---|---|---|
| `backend/` | **甲** | 后端安全内核：认证、RBAC、DID、密钥、数据资产、权限中心、存证、审计 + 算法代理 + WebSocket + 全部 SQL | FastAPI + SQLAlchemy + MySQL 8 + Redis |
| `algo-service/` | **乙** | 算法服务：FedAvg、差分隐私、Top-k、DQN、DeepSeek 适配、分类分级、风险评估 | FastAPI + NumPy（无数据库，独立进程） |
| `frontend/` `deploy/` `packaging/` | **乙** | 前端：4 个新中心页 + 7 个旧页改造；部署与打包：docker-compose、nginx、**双架构离线安装包** | Vue 3 + Vite + Pinia + ECharts + Element Plus |

调用链是单向的，不存在环：

```
浏览器 → frontend(nginx:80) → backend:8000 → algo-service:8100
                                  ↓
                            mysql:3306 / redis:6379
```

**前端永远不直接调 algo-service。** 所有算法调用走 backend，才能满足"统一鉴权网关 + 全链路审计埋点 + 存证上链"的硬性要求。

## 三、铁律（违反会导致合并失败）

1. **`contract/` 目录是冻结区，任何一方不得修改。** 需要改动时当面商量，一人改、另一人同步，并在 `contract/README.md` 追加变更记录。
2. **绝不碰对方的目录。** 甲只写 `backend/`，乙只写 `algo-service/` `frontend/` `deploy/` `packaging/` 和根目录的 `docker-compose.yml` `.env.example`。
3. **接口以 `contract/API-CONTRACT.md` 为唯一准绳。** 觉得契约有问题 → 找对方，不要自己改代码绕过去。
4. **字段名一个字母都不许改。** 前端拿 `pvOutput` 就写 `pvOutput`，后端返回也必须是 `pvOutput`。
5. 每人在自己目录内写「假的对方」作为开发桩（甲写 `backend/tests/fake_algo.py`，乙写 `frontend/src/mocks/`），保证不等对方就能自测。

## 四、怎么合并

合并 = 把三个顶层目录并排放好，**文件路径零交集，不会有冲突**：

```
Zhi_softwire/
├── docker-compose.yml      乙
├── .env.example            乙
├── contract/               冻结区
├── backend/                甲
├── algo-service/           乙
├── frontend/               乙
├── deploy/                 乙
└── packaging/              乙
```

合并后执行：

```bash
cp .env.example .env
docker compose up -d --build
# 浏览器打开 http://localhost，用 admin/admin123 登录
```

跑通 `contract/API-CONTRACT.md` 第六部分的 12 条验收清单，即算完成。

安装包的完整规范见 `安装包规范.md`，两个产物：`energy-tds-v1.0-linux-x86_64.tar.gz` 和

> **W1 就要验的一件事**：如果打算用现有那台树莓派做演示机，先在上面执行 `uname -m`。
> 返回 `armv7l` 说明刷的是 32 位系统，`mysql:8.0` 没有 armv7 镜像，必须重刷 64 位 Raspberry Pi OS。
> 这件事拖到 W5 才发现会非常被动。

**每周五必须做一次真合并**（不是等到第五周才合），把两边代码放一起 `docker compose up`，早暴露问题。

## 八、答辩演示脚本（最终要跑通的故事线）

1. `admin` 登录 → 首页驾驶舱展示可信数据空间全景流程
2. 身份接入中心：现场注册一个设备 DID → 展示 DID 文档 → 验签通过
3. 数据资产中心：登记一条光伏数据 → 自动分级 L3 → SM3 摘要上链
4. 权限控制中心：`subject` 申请读权限 → `admin` 审批 → 授权生效
5. **越权演示**：`vpp` 尝试下发调度指令 → 被拦截 → 审计告警实时弹出
6. 隐私计算：启动联邦学习 → 收敛曲线实时增长 → 隐私预算逐轮消耗 → 每轮梯度哈希上链
7. 云端调度：DQN 生成策略 → DeepSeek 解释原因 → `admin` 签名下发 → 终端回执
8. **防篡改演示**：手动篡改一条存证 → 完整性校验立刻标红 → 链状态显示断裂点
9. 审计中心：用任务 traceId 查出从登录到下发的完整链路
10. **拔网线**：除 DeepSeek 降级为缓存外，全部功能正常
