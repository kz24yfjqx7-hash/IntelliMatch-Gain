## 2. 环境与方法

- 每个契约接口至少 1 正向 + 1 异常（1001/1002/1003/1004/1005/1006/1007/2001 按接口语义覆盖）；字段名、枚举值与契约示例逐字比对（`has_keys`），分页结构 `items/total/page/size`。
- 密码学：本地用 `backend/core/gm_crypto`（只读导入）生成 SM2 密钥、签名、SM3 重算 DID / payload_hash / block_hash，与服务端结果比对。
- 数据库：pymysql 直连 `energy_tds` 核对 information_schema、种子数量、bcrypt、私钥密文、分表、存证链逐条重算。
- 2001 与 DeepSeek 降级：不停任何人的服务，另起隔离副本（backend@5300 指向不可达算法地址；algo@5301 指向不可达 DeepSeek），用完即退。
- 环境噪声：其他 Agent 同时在同一库上演示 tamper（`pvOutput: 999.9`），脚本在存证节开头自动 `restore` 并记录；种子计数按 id 范围过滤。

### 6.1 接口级 RBAC 矩阵（6 角色 × 关键写/读接口）

主题：**不同身份登录后可用功能不同**，其硬边界由后端网关 `@require_permission` / `require_roles` 强制。本矩阵把 6 角色对 6 个关键接口的期望 `code`（**0 = 放行 / 1003 = 越权拒绝**）列全，与后端种子矩阵 `sys_role_permission` 及各接口装饰器逐格一致，可与前端 `v-permission` 裁剪结果（《测试文档.md》§4.1 分角色登录界面核对表）对账。`own` = scope 仅自有：接口放行但结果集/资源属主被收窄。

| 接口（门控） | admin | grid | vpp | subject | regulator | edge | 权威依据（装饰器 / 用例） |
|---|:--:|:--:|:--:|:--:|:--:|:--:|---|
| `POST /assets`（`asset:write`，登记资产） | 0 | 1003 | 0 | 0 (own) | 1003 | 0 (own) | `@require_permission("asset","write")`；regulator 拒绝 API-ASSET-15、subject own API-ASSET-11/12 |
| `POST /dispatch/tasks/{id}/issue`（`dispatch:issue`，签名下发） | 0 | 0 | 1003 | 1003 | 1003 | 1003 | `@require_permission("dispatch","issue")`；vpp 拒绝 API-DP-06、越权记 high 审计 + R01 |
| `POST /fl/tasks`（`algo:execute`，创建并启动联邦学习） | 0 | 0 | 1003 | 1003 | 1003 | 1003 | `@require_permission("algo","execute")`；vpp 拒绝 API-FL-04/05、subject API-DP-04、TC-31-12 |
| `POST /users`（`require_roles(sys_admin)`，用户管理） | 0 | 1003 | 1003 | 1003 | 1003 | 1003 | `require_roles("sys_admin")`；vpp API-USER-02/10、非 admin 五角色 TC-31-10 |
| `GET /audit/*`（`require_roles(sys_admin, regulator)`，审计中心） | 0 | 1003 | 1003 | 1003 | 0 | 1003 | `require_roles("sys_admin","regulator")`；grid TC-31-12、subject API-AUD-19、vpp API-AUD-12/18 |
| `GET /evidence`（`evidence:read`，scope=own 收窄） | 0 | 0 | 0 | 0 (own) | 0 | 1003 | `@require_permission("evidence","read")`；edge 无 `evidence:read`→1003（API-EV-18 / TC-31-12）、subject 列表仅自有 API-EV-17/17b |

> **scope=own 行为**：`asset:write` / `evidence:read` 的 own 角色（subject、edge 的资产）接口本身放行 code 0，但后端在 SQL 层按 `actor_did`/属主收窄——`GET /evidence` subject 列表只返回自有存证（API-EV-17，`total` 全为自有），读他人存证详情/凭证返回 1003（API-EV-17b，B-002 已修复）；`scope=all` 的 sys_admin / grid_dispatcher / vpp_operator / regulator 不受收窄影响。资产同理（API-ASSET-11~13）。
